# X 投稿文

デフォルトでは投稿文を作るだけにし、外部アカウントへ投稿しない。投稿操作はユーザーが明示した場合だけ行う。

## 記事から投稿文を作る

1. 記事を読み、想定読者が経験する場面と、その人に役立つ発見を一つ選ぶ。
2. 書き出しには具体的な場面、身近な疑問、考えが変わった点のいずれかを置く。「記事を書きました」やタイトルの再掲を定型の書き出しにしない。
3. 発見を一つ伝え、短い具体例や根拠を添える。基本形は「場面・問い → 発見 → 根拠・具体例」とし、2〜3 文を目安に整える。
4. 投稿だけでも一つの知見が伝わるか確認する。問いだけで終えず、記事が示す答えや判断条件を含める。未解決の問いを扱う場合は、分かっていることと未解決の範囲を書く。
5. 記事への案内を含める場合は、末尾に正規 URL を一つ置く。カードに表示される title や description の繰り返しで本文を埋めない。

記事への案内を含む投稿の型:

```text
<読者が経験する具体的な場面や疑問。>
<記事で得た発見を一つ。短い根拠や具体例、必要な適用条件を添える。>

https://hideshi.github.io/blog/YYYY/MM/DD/slug/
```

## 一本の記事から別の入口を作る

複数案や継続投稿を作る場合は、次のうち記事に材料がある切り口を選ぶ。同じ告知の言い換えにせず、各案を単独で読める内容にする。

| 切り口 | 投稿に含めること |
| --- | --- |
| 調べるきっかけになった疑問 | 読者にも身近な問いと、調べて分かったこと |
| 意外だった発見・考えの変化 | どの理解を、どの根拠によって見直したか |
| 実務の具体例 | 誰が何に迷い、どの条件で判断が変わるか |
| 図による説明 | 一つの比較や関係と、それをどう読むか |
| 残る問い・研究の限界 | 説明できた範囲と、まだ確かめられていない点 |

- リンクなしで知見を伝える投稿と、要点に記事リンクを添える投稿を、依頼に応じて作り分ける。
- 時間を分けて紹介する場合は、別の切り口を選び数日空ける案を示す。投稿予定の作成や予約は依頼がある場合に行う。
- 図は一つの比較や関係に絞り、図中の条件・出典と本文の説明を対応させる。
- 経験や考えの変化は、記事またはユーザーの説明にあるものだけ使う。原典の主張、筆者の推論、実践での観察を混同しない。

## 仕上げの確認

- 280 字以内。CJK 文字は通常 2、URL は t.co 換算で 23 と見積もる。
- ハッシュタグは原則付けない。
- 初回は末尾 `/` のある正規 URL を使い、クエリを付けない。
- 本文を読まないと解けない比喩や造語を投稿文へ置かない。
- 「誰が、何を、いつ、なぜする話か」が投稿文だけで分かるか確認する。
- 煽り、過度な一般化、根拠のない断言を避け、短縮しても主張に必要な条件や研究の限界を落とさない。
- 読者へ問いかける場合は、本文に関係する具体的な経験や判断を尋ねる。反応を求めるだけの呼びかけは足さない。

## カードが古い、または欠けた場合

- まず公開ページと `twitter:image` の双方が 200 を返し、JPEG が反映済みか確認する。
- 新しい共有に限り、ページ URL へ `?v=2` を付けて再取得を促せる。画像 URL にはクエリを足さない。
- 投稿済みポストのカードは差し替えられない場合がある。必要なら反映後に新しい URL で投稿し直す。
- 下書き画面のプレースホルダーだけで失敗と断定しない。
